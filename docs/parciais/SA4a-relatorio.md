## 3. Decisões técnicas (não mudam o combinado)

1. **Faixas = tabela, não código** (regra do Documento Mestre): mudar faixa é versão nova; a API lê a vigente. `proposal` vai em cada faixa e em cada alerta.
2. **Alerta é leitura.** Calculado na API a cada pedido; nenhuma escrita, gatilho ou job olha para ele (provado no pytest e no roteiro).
3. **Margem** = 1 − custo de IA em R$ ÷ (créditos cobrados × crédito de referência da faixa), como o protótipo; o crédito de referência (R$ 0,50) e o câmbio (5,40) saem marcados em `margin_basis.provisional`.
4. **Tendência** = custo por turno nos últimos 7 dias ÷ nos 7 anteriores − 1, as duas janelas terminando no fim do período; sem turno numa das janelas, nula (não alerta). Conjunto: média das contas ponderada pelo custo (fórmula do protótipo).
5. **Turno = run com chamada de IA** (cada resposta de um agente, de conversa ou de entrega), no dia em que o run nasceu.
6. **Chamada de IA inclui a autoverificação** (`kind = 'check'` chama o modelo; a SA1 contava só `llm_call`). Vale em Consumo, Modelos e custos e Saúde; o custo já incluía.
7. **Custo da qualidade de `run_steps`** (a SA1 usava `runs.cost_usd`): o worker grava `runs.cost_usd` = soma das etapas (`store._totals`), então o número é o mesmo; só fica atual também para o run ainda rodando.
8. **Versão de prompt da entrega** = a do primeiro run do trabalho que registrou versão (o que produziu a v1), porque "aprovada de primeira" fala da v1.
9. **Erro do agente** = autoverificação reprovada (`payload.approved = false`) ou resposta fora do formato (`llm_invalid_output`); **chamada com falha** = etapa com falha (como o "como ler" do protótipo).
10. **Saúde:** gasto de `run_steps` só onde há etapa (Anthropic; motor de imagem pelo `imagem.gerar`, hoje US$ 0); e-mail conta envios e falhas por função que só devolve contagens; Asaas e Mercado Pago sem números até a conta existir (estado vazio honesto).

## 4. Onde discordei ou li diferente

1. **"Última recusa por saldo" não é detectável hoje.** O adaptador da Anthropic transforma qualquer 4xx em `llm_config` guardando só status e tipo, sem distinguir saldo insuficiente; o runtime simulado nunca recusa. A API devolve `last_balance_refusal_at` de `provider_health` (vazio). Para detectar de verdade, o adaptador precisa reconhecer o erro de cobrança da Anthropic; isso exige conferir o formato atual do erro no `claude-api` antes de mexer no runtime — fica para quando a chave chegar.
2. **Estado do provedor:** só o da Anthropic é calculado (simulado sem chave; com chave, falhando se a última falha é mais nova que o último sucesso); os outros vêm de `provider_health`, como na SA1.
3. **Contagem de chamadas** mudou para incluir a autoverificação (decisão 6): é correção de contagem, não de contrato (mesmos campos). Se o dono preferir "chamada" só como produção, é uma linha nas views.

- **Consumo (`consumo.js` → `GET /admin/consumption`):** `uso30[conta]` → `items[]` (`requests` = trabalhos; `credits_charged` = créditos; `ai_cost_deliveries_usd`/`ai_cost_conversation_usd` = custo de entregas/conversa; `ai_cost_usd`/`ai_cost_brl`; `llm_calls`; tokens; `turns`); `iaPorCredito`/`margem`/`tendencia` → `items[].economics.{ai_cost_per_credit_brl, gross_margin, cost_per_turn_trend}` e `cost_per_turn_usd`; `fora` → `economics.alerts[]` (`metric`, `value`, `threshold`, `comparison`, `proposal`); conjunto filtrado e linha de total → `totals` + `economics` + `trend_accounts` ("média de N contas"); `faixas` → `alert_rules[]` (marcar **Proposta**); `CREDITO_REF`/`CAMBIO` → `margin_basis` (marcar **Provisório**). Período: `since`/`until` (o protótipo estimava 7 dias como 7/30 de 30; a API calcula o período de verdade). Série por dia/semana/mês: `granularity` + `series`.
- **Alertas (`GET /admin/alerts`):** contas em alerta e saldos abaixo do limiar — serve também para os contadores da barra lateral que a SA2 deixou de fora (§5 da SA2).
- **Qualidade (`qualidade.js` → `GET /admin/quality` e `/admin/quality/compare`):** `porTipo` → `by_type` (`key` = delivery; `deliveries`; `approved_first_time ÷ deliveries` = de primeira; `adjustments ÷ deliveries`; `not_approved`; `ai_cost_per_approved_usd`; `agent_errors`; `failed_steps` = chamadas com falha); `porMes` → `by_month` (`key` AAAA-MM); a "nota" do mês (o que mudou) → `by_prompt_version` (agente, hash, `origin`, `sources[].kind/key/version`, `first_used_at`) — o texto livre do protótipo não existe no banco; `COMO` → `how_to_read` (mandar `locale`); "Comparar dois meses" → `/admin/quality/compare` com o primeiro e o último dia de cada mês (`rates` e `delta` prontos; `prompt_versions` de cada lado).
- **Saúde (`saude-apis.js` → `GET /admin/providers` e `PATCH …/balance`):** `estado` → `status` (`working`, `failing`, `simulated`, `local_only`, `not_integrated`, `account_not_created`); `chave` → `key` (`configured`/`missing`/`not_applicable`); `chamadas24`/`falhas24` → `calls_24h`/`failures_24h` (+ `calls_7d`/`failures_7d`); `gasto.{h24,d7,inicio}` → `spend_usd.{h24,d7,d30,total}`; `ultimaFalha`/`ultimaFalhaTxt` → `last_failure_at`/`last_failure_text`; `ultimaRecusaSaldo` → `last_balance_refusal_at`; `saldo`/`alerta`/`moeda` → `reported_balance`/`alert_below`/`reported_balance_currency` + `balance_alert` + `balance_history`; `hoje` → `note`. Formulário "informar saldo": `amount`, `currency` (3 letras), `read_at`, `reason` (10–500), `alert_below` opcional; erros 422 com `details` por campo, 404 provedor.
